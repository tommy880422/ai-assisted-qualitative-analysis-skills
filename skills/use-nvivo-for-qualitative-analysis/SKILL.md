# Use NVivo for Qualitative Analysis

Implement a declared analytic method in NVivo while preserving source context, case structure, decisions, and recoverability. Confirm the installed NVivo version and interface before giving click-by-click instructions because labels and locations can change.

## Workflow

1. **Confirm the method.** State the methodology, analytic approach, data types, cases, units, comparisons, and intended outputs. Invoke the appropriate design or analysis skill first if these are unsettled.
2. **Design the project before importing.** Read [project-architecture.md](references/project-architecture.md). Define folders, naming, IDs, classifications, attributes, memos, versioning, and backups.
3. **Import and verify.** Import files, datasets, transcripts, media, notes, and bibliographic material; check completeness, encoding, speaker structure, timestamps, and anonymization.
4. **Create analytic structure.** Read [coding-cases-classifications.md](references/coding-cases-classifications.md). Distinguish files, codes, cases, classifications, attributes, sets, relationships, and links.
5. **Code and memo iteratively.** Keep method decisions outside the software's default behavior. Revise codes and cases with documented consequences.
6. **Explore and query.** Read [queries-matrices-visualizations.md](references/queries-matrices-visualizations.md). Use queries to answer declared analytic questions and inspect returned source context.
7. **Use special workflows selectively.** Read [special-workflows.md](references/special-workflows.md) for focus groups, multimedia, social media, surveys, mixed methods, and literature reviews.
8. **Manage teamwork and AI.** Read [team-ai-and-audit.md](references/team-ai-and-audit.md). Protect privacy, document automation, reconcile project copies, and preserve an audit trail.
9. **Export and archive.** Export evidence tables, reports, codebooks, classifications, memos, visuals, and a recoverable project package. Test backups and, when needed, REFI-QDA exchange.

## Required Output

Scale the answer to the request. A narrow question — one decision, one section, one paragraph to revise — gets a direct answer plus only the items that bear on it. Produce the full set below when the user is planning or writing up the whole study, or asks for it.

Return:

- method-to-NVivo mapping;
- project architecture and naming convention;
- import and verification checklist;
- case, classification, attribute, code, memo, and relationship plan;
- query plan tied to research questions;
- backup, version, collaboration, privacy, and AI controls;
- export and audit package.

Write in the user's language. When the user writes Chinese, reply in 正體中文 using Taiwanese methodological terminology, and give every method, criterion, and software term its English original in parentheses at first use — the literature, the thesis examiners, and the software interface all use the English form.

## Guardrails

- Do not use word frequency, autocoding, sentiment, or AI themes as findings without contextual human analysis.
- Do not create a case for every file automatically; define the analytic unit first.
- Do not encode demographic attributes repeatedly as text codes when classifications are the correct structure.
- Do not infer relationships from code co-occurrence alone.
- Do not allow software hierarchies to become theoretical hierarchies by accident.
- Do not overwrite the only project copy or rely on an untested backup.
- Do not merge team projects without compatible structure, IDs, and version control.
- Do not provide version-specific menu paths without verifying the user's installed version or current official documentation.
