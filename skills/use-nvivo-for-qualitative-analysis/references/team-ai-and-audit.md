# Team Projects, AI, and Audit

## Team Setup

Before coding:

- choose separate-copy or integrated collaboration;
- align software version and project structure;
- assign stable analyst IDs;
- freeze or version classifications and code definitions;
- define who can add, rename, merge, or delete project objects;
- schedule calibration and merge points;
- maintain a master change log and backup owner.

## Merge Controls

1. Back up every project copy.
2. Check shared IDs, code names, classifications, and attributes.
3. Review structural changes before import or merge.
4. Merge into a copy of the master.
5. inspect duplicate items, unmatched cases, code proliferation, and memo authorship;
6. validate counts and a sample of source links;
7. promote the merged copy only after review.

## AI and Automatic Coding

Distinguish:

- deterministic formatting-based coding;
- speaker-name or paragraph-style autocoding;
- range coding;
- sentiment models;
- topic or theme suggestions;
- machine-learning replication of existing coding.

For every automated operation:

- preserve the pre-operation backup;
- record tool, version, settings, training material, and date;
- run on a test subset first;
- inspect false positives, false negatives, bias, and context loss;
- store automated coding separately until reviewed;
- never represent machine suggestions as researcher-validated themes.

## Audit Package

Export or archive:

- project data dictionary;
- source inventory and import log;
- codebook with versions;
- case classifications and attribute definitions;
- method, reflexive, code, and category memos;
- saved query definitions and interpretation notes;
- team calibration or comparison records;
- AI operation records;
- evidence matrices and reports;
- final project, backup test record, and exchange export when needed.

Exports carry the raw material with them. An evidence matrix, a coding report, or a REFI-QDA package reproduces source text verbatim, including anything the anonymization pass missed and any identifying detail that only becomes identifying once assembled in one table. Check every export against its intended recipient before it leaves the project, and keep exports destined for supervisors, coauthors, or appendices under the same consent terms as the data itself.
