# JTBD Quality Gate Checklist

Single auditable checklist, merged from the working gates in `SKILL.md` and the final review in
`references/academic-writing-and-quality.md`. Those two lists overlapped; this file is now the canonical
version, so record results here rather than maintaining a third copy.

**How to use.** Copy per study. Fill `Evidence location` with the file, section, or log where the check can
be verified — not with a tick alone. `n/a` is a valid status but must carry a reason. Attach the completed
file to the audit trail (`academic-writing-and-quality.md` section 9).

Status values: `pass` / `fail` / `n/a` / `pending`.

---

## A. Theory and constructs

| ID | Check | Passing looks like | Evidence location | Status | Date |
|---|---|---|---|---|---|
| A1 | Variant integrity | One primary formulation named and justified; any secondary one bounded to a stated subquestion; incompatible constructs kept separate | | | |
| A2 | Adjacent approaches not conflated | I-Corps, disruption theory, and journey mapping reported separately from the JTBD formulation, never as it | | | |
| A3 | Construct validity | Job, circumstance, need, outcome, solution, feature, activity, journey stage, and stakeholder role each operationally defined and distinguished | | | |
| A4 | "Need" disambiguated | The formulation's own definition of need is stated and used consistently; no generic sense imported | | | |
| A5 | Solution neutrality | Job statements and outcomes contain no product, brand, channel, or feature | | | |
| A6 | Terminology stability | One glossary in force; Chinese/English terms consistent throughout; no drift between chapters | | | |

## B. Design and sampling

| ID | Check | Passing looks like | Evidence location | Status | Date |
|---|---|---|---|---|---|
| B1 | Chain of reasoning intact | Purpose → question → formulation → constructs → unit → sampling → data → analysis → claim, with no broken link | | | |
| B2 | Unit of analysis | Job episode is the unit, or another unit is explicitly justified; episodes per participant recorded | | | |
| B3 | Sampling contrasts | Theoretically consequential contrasts present, not only loyal current users | | | |
| B4 | Consequential roles | Each stakeholder role sampled sufficiently for within-role analysis before cross-role synthesis | | | |
| B5 | Role of JTBD named | Sensitizing lens, analytic framework, explanatory proposition, or applied process — stated, not implied | | | |

## C. Data generation

| ID | Check | Passing looks like | Evidence location | Status | Date |
|---|---|---|---|---|---|
| C1 | Episode evidence | Every core interpretation anchored in one or more identifiable episodes | | | |
| C2 | Non-leading instruments | Participants not taught JTBD vocabulary, not asked to approve job statements, not shown solutions before the current story | | | |
| C3 | Temporal evidence | Triggers, consideration, choice, use, and aftermath reconstructed where switching is explained | | | |
| C4 | Non-action covered | Delay, doing nothing, workarounds, and nonconsumption elicited, not only adoption | | | |
| C5 | Instrument versioning | Versions logged, with which cases used which version | | | |

## D. Analysis

| ID | Check | Passing looks like | Evidence location | Status | Date |
|---|---|---|---|---|---|
| D1 | Context preserved | Case summaries written before fragmenting data; context retained before cross-case coding | | | |
| D2 | Method named, not lens | The actual analytic procedure is reported and cited; "analysed using JTBD" does not appear alone | | | |
| D3 | Evidence layers separate | Participant wording, researcher paraphrase, code, and higher-order interpretation stored distinctly | | | |
| D4 | Evidence strength distinguished | Direct account, observed behavior, documentary trace, and researcher inference labelled | | | |
| D5 | Competing explanations | Price, access, habit, institutional rules, social norms, and researcher prompting considered | | | |
| D6 | Negative cases | Exceptions reported and scope conditions revised, not hidden | | | |
| D7 | Big Hire / Little Hire | Separated wherever adoption and actual use could diverge | | | |
| D8 | Stakeholder jobs separate | No blended "customer job" in multi-actor settings | | | |
| D9 | Traceability | Every finding links to case IDs and source locators without exposing identities | | | |
| D10 | Evidence table validated | `validate_evidence_table.py` run without errors on the version behind reported findings | | | |

## E. Quantification (ODI) — mark `n/a` if there is no quantitative phase

| ID | Check | Passing looks like | Evidence location | Status | Date |
|---|---|---|---|---|---|
| E1 | Constructs stabilized first | Job map and outcome statements fixed before ratings were fielded | | | |
| E2 | Scale declared and correct | Rating scale, transformation to the analysis scale, and resulting range all stated | | | |
| E3 | Threshold justified | Threshold declared and appropriate to the scale, not a default carried over from 0–10 | | | |
| E4 | Formula and parameters reported | Formula, table-stakes cutoff, overserved rule, and sample size reported alongside every score | | | |
| E5 | Uncertainty and sensitivity | Uncertainty reported; sensitivity run at alternative thresholds with rank stability shown | | | |
| E6 | Segmentation discipline | If segmenting: respondent-level data, justified model, stability and validation examined | | | |

## F. Claims and writing

| ID | Check | Passing looks like | Evidence location | Status | Date |
|---|---|---|---|---|---|
| F1 | Claims discipline | Source claims, empirical findings, interpretation, and design recommendation separated | | | |
| F2 | Method coherence | No statistical generalization from qualitative samples; no causal effects from retrospective narratives | | | |
| F3 | Limits explicit | Causality, prevalence, transferability, and effectiveness limits all stated | | | |
| F4 | Practitioner claims appraised | Commercial success claims attributed and critically appraised, never treated as independent validation | | | |
| F5 | Job spec placed correctly | If produced, it appears as a design implication, not as a finding, with unevidenced fields left visible | | | |
| F6 | Reporting standard completed | COREQ or SRQR completed against the published item wording, plus the JTBD-specific additions | | | |

## G. Ethics and citation

| ID | Check | Passing looks like | Evidence location | Status | Date |
|---|---|---|---|---|---|
| G1 | Identifiable detail minimized | Sensitive and identifying detail minimized, especially in health and workplace research | | | |
| G2 | Power, burden, equity | Whose job is privileged, who receives value, and who bears cost or risk are all examined | | | |
| G3 | Recruitment independence | Participation could not affect employment or care; consent separated from service provision | | | |
| G4 | Citation discipline | Bibliographic facts and page anchors verified against the actual edition; copyrighted work paraphrased and quoted sparingly | | | |
| G5 | No fabrication | No invented participants, quotations, statistics, citations, page numbers, or saturation claims | | | |
| G6 | Sources not redistributed | Restricted PDFs not bundled or reproduced | | | |
