# 編碼手冊與紀錄的格式

這些欄位是為了讓每一筆編碼都能回到原文、每一次修改都能回到決定。研究者可以增減欄位，但「依據原句」「判定狀態」「修改紀錄」三項建議保留。

## 一、類別系統

把類別分成幾組，各組的來源與用途不同，分開記錄才不會混淆。

| 類別組 | 來源 | 說明 |
|---|---|---|
| 理論類別 | 演繹（由理論文獻） | 理論的構念。每個類別註明出自哪一份文獻的哪個概念 |
| 實質代碼 | 歸納（由資料） | 受訪者實際談到的內容。註明是在哪一場形成的 |
| 描述標記 | 分析需要 | 例如發言依據的是親身經驗、假設情境或一般看法；焦點團體另可標記團體互動（附和、反對、追問） |

這三組是為了記錄來源而分的，不是 Kuckartz 與 Rädiker 的用語。寫方法章時用書上的用語說明，對應如下。

| 本範本 | 書上的用語 | 依據 |
|---|---|---|
| 理論類別 | 演繹發展的主類別（main category），類型上是理論類別（theoretical category） | 3.1 節（pp. 51–59）；類別類型見 2.2 節（pp. 35–37） |
| 實質代碼 | 由資料歸納的類別。隸屬於某個理論類別時，是該主類別的次類別（sub-category）；自成一組時，是另一組歸納形成的主類別與次類別，要寫明是哪一種 | 3.2、3.3 節（pp. 59–76）；先演繹後歸納的合併做法見 3.4 節（pp. 76–77） |
| 描述標記 | 依內容而定：記錄客觀情形的是事實類別（factual category）；依研究者的標準分等級的是評價類別（evaluative category）；屬於整個個案的特徵（年級、組別）記為個案的屬性，不逐段編碼（這一項是本範本的做法） | 類別類型見 2.2 節（pp. 35–37） |

書上不事先劃定「編碼單位」。事先把文本切成固定單位再編碼，是古典內容分析的做法；質性內容分析編的是意義單位，片段可以重疊或互相包含，判斷邊界的標準是離開上下文仍看得懂（pp. 45–46）。所以本範本沒有「編碼單位」欄，而是在第三節寫明片段範圍的規則。

## 二、每個類別要寫的內容

| 欄位 | 內容 |
|---|---|
| 代碼與名稱 | 例如 D3.2 擔心被認識的人看見 |
| 類別類型 | 理論、主題、評價、分析、事實、自然（受訪者自己的用語）等，依書上 2.2 節。類型不同，編碼時要求的判斷也不同 |
| 層級 | 主類別、次類別，或個案的屬性 |
| 定義 | 一到兩句 |
| 何時編 | 具體的判斷線索 |
| 何時不編／區辨 | 與相近類別的差別，改編哪一個 |
| 例句 | 取自資料，附編碼 ID |
| 形成來源 | 理論（文獻）或資料（場次） |

## 三、判斷規則與邊界案例

- **片段範圍：** 寫在最前面。以完整的意思為單位；一個意思跨幾句或幾段就編成一段；理解發言所必需的提問一併納入；片段離開上下文仍要看得懂（Kuckartz 與 Rädiker，2023，p. 105）。同一段可以編到多個類別。
- **計數單位：** 寫明之後計數時算的是個案數還是片段數，焦點團體的個案是整場還是個人（p. 90）。
- **判斷規則：** 跨類別的通則，逐條編號。例如「依據原句必須在片段範圍內」「一般性看法須能連回本人處境才計為本人的情形」。
- **邊界案例決定：** 研究者對個別案例的裁決。欄位：編碼 ID、問題、選項、決定、理由、日期。日後遇到同類情形比照辦理。

## 四、編碼表（每場一張）

| 欄位 | 說明 |
|---|---|
| 編碼 ID | 場次加序號，例如 S1-C016。事後補編的列在前一列 ID 後加 a、b，不重排 |
| 行號起、行號迄 | 對應標準版逐字稿 |
| 受訪者（代號）、組別 | |
| 原文 | 片段全文 |
| 依據原句、依據行號 | 支持這筆編碼的原句，必須逐字取自片段 |
| 各類代碼 | 每一類別組一欄 |
| 判定狀態 | 該類空白時填原因：不適用、資料不足、待決 |
| 分析備忘 | 判斷理由；修改時寫「日期、原值→新值、理由、誰決定」 |
| 初步編碼者 | 例如 AI 工具名稱 |
| 狀態 | 待研究者確認、已確認 |

## 五、版本紀錄

| 版本 | 日期 | 修改內容 | 依據 | 草擬者與決定者 |
|---|---|---|---|---|
| v0.1 | | 建立初版 | 理論文獻；第一場逐字稿 | AI 草擬，待研究者審閱 |
| v0.2 | | …… | 研究者某日的決定 | 研究者決定，AI 修改 |

新增代碼或改了定義的版本，在「修改內容」寫明重判了哪幾場、幾列。沒有重判就寫沒有重判與原因。

最後一欄要寫清楚。日後寫揭露時，這一欄就是「誰做了什麼」的證據。

## 六、AI 輔助檢視的修改紀錄

| 編碼 ID | 類別 | 原值 | 檢視工具甲 | 檢視工具乙 | 複核結果（修改／維持／交研究者） | 理由 | 日期 |
|---|---|---|---|---|---|---|---|

另外保留一份檢視前的原始比對結果，不要覆蓋。報告方法時以檢視前的數字為準。
