# 各階段可直接複製的指令

【 】內換成自己的研究內容。每一則都寫明工具該做什麼、不能替研究者決定什麼。可以貼給任何對話式 AI 工具使用。

每一則會讀到研究資料的指令，貼出去之前先確認兩件事：這個工具可以讀哪一種版本的資料（對照倫理審查的核准內容）；附件是不是那個版本。雲端的 AI 服務原則上只給去識別化的版本，去識別化由研究者自己或用本機程式先做好，不要請雲端 AI 代做。

## 階段 0　錄音轉錄與逐字稿整理

### 整合兩個來源的逐字稿

```text
附件是同一場訪談的兩份逐字稿（版本：【去識別化版本／原稿，原稿須在核准範圍內】），分別由【轉錄工具甲】和【轉錄工具乙】產生。
請逐段比對，整合成一份逐字稿：
1. 兩份一致的地方直接採用。
2. 兩份不一致的地方，不要自行決定，把兩種寫法並列，標上【待確認】與時間點，我會回去聽錄音。
3. 說話者無法確定時標【說話者待確認】，不要猜。
4. 轉錄規則是【研究者定的規則，例如保留語氣詞、重複與停頓】。不要潤飾，不要補上錄音裡沒有的字。
最後列出所有待確認之處的清單。
```

### 統一逐字稿格式

```text
這是【N】場訪談的逐字稿，格式不一致。請先告訴我哪一份最適合當標準格式與理由。
我同意後，把其中一份改成標準版給我看（另存新檔，原檔不動，每段加行號），我確認模板後再處理其他場。
只改格式，不改任何一個字的內容。
```

## 階段 1　初步閱讀、個案摘要與理論架構

### 初步閱讀與個案摘要

```text
附件是【N】場訪談的逐字稿。在套用任何理論或類別之前，請先為每個個案寫一份簡短的摘要。
本研究的個案是【整場團體／個別受訪者】。
每份摘要包含：這個個案談了哪些與研究問題有關的內容、特別值得注意的段落（附行號）、與其他個案明顯不同之處。
只描述逐字稿裡有的內容，不要詮釋、不要歸類、不要評價。
另外列出你覺得之後分析時值得留意的地方，標明這是你的觀察，我會自己讀過逐字稿後寫備忘。
```

### 依理論做初步分析、選擇分析架構

```text
附件是【N】場訪談的逐字稿，各場受訪者的特徵是【分組方式】。
請以【理論名稱與主要文獻】為視角做初步分析，說明各組資料中與理論各構念有關的內容，每一點附原句與行號。
這個理論有不同的版本或做法時，請並列各自的適用條件與對我的研究設計的影響，由我選擇，不要替我決定。
只根據逐字稿，不要加入資料裡沒有的推論。
```

## 階段 2　建立與修訂編碼手冊

### 由理論建立演繹類別、由資料歸納實質代碼

```text
我的研究以【理論名稱與主要文獻】為分析視角，分析方法是【例如 Kuckartz 與 Rädiker 的結構式質性內容分析】。
請依附件的理論文獻草擬演繹類別，每個類別寫出：定義、何時編、何時不編、與相近類別的區辨。例句先留空，不要自己造句。
先用【指定的幾場，建議選性質不同的場次】試用這些演繹類別，指出哪些定義套不上資料，並從資料裡為每個類別找例句，附行號。
再由同一批逐字稿歸納實質代碼，分兩部分：
(1) 在每個理論類別底下，由編到該類別的內容歸納次類別；
(2) 與研究問題有關、但理論類別沒有涵蓋的內容，另外歸納。
每個代碼附原句與行號，註明屬於哪一個理論類別（或不屬於任何一個），以及是在哪一場形成的。
定義不清或可以有兩種判法的地方，不要自己決定，列成待決事項，附原文與選項，由我決定。
```

### 先試編再全面編碼

```text
請挑共【40】個片段試編，各場、各組都要有，並包含沒有用來建立手冊的場次。先給我抽樣清單和挑選理由，我確認後再編。
試編後，把規則不夠清楚、你沒有把握的地方列成問題，附前後文，一題一題問我。
```

## 階段 3　六場的編碼

### 依手冊逐場編碼

```text
請依編碼手冊【版本】編碼【第 N 場】。每筆編碼要有：片段行號、依據原句（必須是片段內的原文）、各類代碼、判斷理由。
片段的範圍以完整的意思為界，離開上下文仍要看得懂；理解發言所必需的提問一併納入。
手冊沒有涵蓋的情形不要硬編，標為待決並說明。
出現手冊沒有的新內容時，不要自行新增代碼，請提出建議，附原文與行號，並說明是新的概念還是既有代碼的變化，由我決定。
編完一場先給我看，我確認後才編下一場。
```

### 新增代碼或修改定義之後

```text
手冊已改為【版本】，修改內容是【新增的代碼或改動的定義】。
請回到已編完的【第 N 至 N 場】的逐字稿重讀，包括當時沒有編碼的段落：
(1) 找出符合新代碼或新定義、但當時沒有編的內容，列為建議補編，附行號與原句；
(2) 找出已編的列中受這次修改影響的，逐筆提出建議，列出原值、建議的新值與理由。
【若只是把一個已編完的類別再細分，改為：只重看編了該類別的列。】
這些都是建議，我確認後才改。不受影響的列不要動。最後告訴我重讀了幾場、建議補編幾筆、建議修改幾筆。
```

## 階段 4　人工智慧輔助檢視與編碼審視

### 以第二個人工智慧工具檢視編碼（盲判）

```text
你在做 AI 輔助檢視。下面是編碼手冊中【類別】的定義與規則，以及訪談片段（已代號化）。
你看不到原編碼者在這個類別的代碼。請依手冊獨立判斷每個片段的【類別】，並寫出依據的原句與理由。
只依手冊判斷，不要加入手冊沒有的類別。
```

這一則只檢查已選出的片段編得對不對。有提供其他代碼當脈絡時，在紀錄裡寫明提供了哪些。

### 檢查漏編與片段範圍

```text
附件是【第 N 場】的完整逐字稿（已代號化）與編碼手冊。下面是這一場已編碼片段的行號範圍，不含代碼：【行號清單】。
請讀【指定的段落，例如行 1–300】，列出：
(1) 依手冊應該編碼、但不在行號清單裡的內容，附行號、原句與你認為適用的類別；
(2) 清單中的片段，有沒有切掉理解它所必需的提問或前後文。
只列出來並說明理由，不要改任何東西。
```

### 複核不一致之處

```text
請比對原編碼與檢視結果。不一致的列逐筆回到手冊與原文複核，每一列給我一個建議：
建議修改、建議維持，或依手冊無法判定（附原文與兩種判法）。每列寫下依據的手冊條文與理由。
不要直接改編碼表。我確認後才修改；每筆修改留下原值、新值、理由、日期與決定者。
另請從一致的列中隨機抽【N】列給我重看。
若同一個類別有很多不一致，請指出是定義的哪一句造成的，我會考慮修訂手冊。
```

## 階段 5　類別穩定度的評估與結果的歸納

### 類別是否已經穩定

```text
請依手冊的版本紀錄與編碼表整理兩張表：
(1) 每個【實質代碼】是在哪一版手冊、看哪幾場資料時形成的；
(2) 每個代碼在各場第一次出現的位置。
另外指出手冊定稿之後才新增的代碼各是什麼、屬於新的概念還是既有概念的變化，以及哪些分組的資料比較少。
這兩張表只能說明類別在現有資料中是否穩定。資料是否飽和、能宣稱到什麼程度由我判斷，請只提供數字與依據。
```

### 歸納與檢驗研究結果的類別

```text
請把編了【要歸納的類別，寫明是手冊裡的哪一個】的列依【個案或組別】彙整，提出歸納的方案，每一類附全部支持的編碼 ID。
方案提出後，回到個案摘要、其他類別的列與逐字稿中沒有編碼的段落，找不符合這個方案的情形與其他說得通的解釋，附行號。
另列出哪些列放不進任何一類。分類由我比較後定案。
```

## 階段 6　研究結果的撰寫

### 草擬研究結果

```text
請依【歸類表】與編碼草擬【章節】的段落。每個論點要對得到編碼 ID，候選引文附行號並逐字照錄。
只寫資料支持的內容；詮釋的部分標明是你的建議，由我決定是否採用與如何修改。
```

### 核對研究結果與資料

```text
請逐筆核對這一章的每個數字與每段引文：數字要對得到編碼表，引文要與逐字稿原文逐字相符並註明行號。
對不上的列出來，不要自行修改正文。
```
