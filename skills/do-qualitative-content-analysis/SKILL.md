# Do Qualitative Content Analysis

Conduct qualitative content analysis as a systematic, question-led, category-based, and documented interpretive process. Preserve cases as well as categories.

## Workflow

1. **Define the study logic.** State research questions, data types, case unit, the rule for the scope of coded segments and how much context each must carry (QCA does not pre-segment the text into fixed coding units; pp. 45–46, 67), prior knowledge, and intended analytic product.
2. **Choose the QCA type.** Read [method-selector.md](references/method-selector.md): structuring, evaluative, or type-building.
3. **Prepare the data.** Read [transcription-and-anonymization.md](references/transcription-and-anonymization.md) whenever the corpus comes from recordings. Fix the transcription rules, level of accuracy, and anonymization before coding, because they bound what the analysis can later claim.
4. **Begin with the material.** Read a varied subset, write memos, mark notable passages, and prepare initial case summaries before full coding.
5. **Develop categories.** Read [category-development.md](references/category-development.md). Choose deductive, inductive, or combined development and create explicit definitions.
6. **Pilot the category system.** Code a purposive and varied subset, inspect category boundaries, revise the coding guide, and recode affected material.
7. **Code the corpus systematically.** Preserve context and record uncertainty and category-system versions.
8. **Analyze after coding.** Follow [three-workflows.md](references/three-workflows.md). Build thematic case summaries, evaluative profiles, relationships, cross-tabs, or typologies as appropriate.
9. **Assess quality.** Read [quality-and-software.md](references/quality-and-software.md). Use internal checks, coder comparison when methodologically relevant, validity checks, documentation, and claim limits.
10. **Report transparently.** Explain category development, coding, post-coding analysis, quality procedures, software, and the relation between qualitative interpretation and any counts.

## Required Output

Scale the answer to the request. A narrow question — one decision, one section, one paragraph to revise — gets a direct answer plus only the items that bear on it. Produce the full set below when the user is planning or writing up the whole study, or asks for it.

Return:

- selected QCA type and rationale;
- units of analysis and context;
- data-preparation plan covering transcription rules and anonymization;
- category-development plan;
- category system and coding-guide template;
- pilot and revision protocol;
- method-specific post-coding analysis plan;
- quality and documentation plan;
- methods and findings outline.

Write in the user's language. When the user writes Chinese, reply in 正體中文 using Taiwanese methodological terminology, and give every method, criterion, and software term its English original in parentheses at first use — the literature, the thesis examiners, and the software interface all use the English form.

## Guardrails

- Do not reduce QCA to counting words or codes.
- Do not treat categories, codes, and themes as interchangeable without defining their roles.
- Do not build categories unrelated to the research questions.
- Do not use an all-deductive system without testing it against empirical material.
- Do not stop at coding; complete the analysis of cases, categories, relations, evaluations, or types.
- Do not treat intercoder agreement as validity or require it in every project.
- Do not import reflexive-TA claims about theme development into this category-based method.
