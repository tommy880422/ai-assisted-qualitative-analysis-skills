# Three QCA Workflows

Each workflow below follows the phase structure and numbering of the source method. Keep the numbering when writing the method section, so a reader can match the reported procedure to the published one.

## Structuring QCA: Seven Phases

1. **Initial work with the text.** Read, write memos, mark notable passages, and produce brief case summaries.
2. **Develop main categories.** Usually derived deductively from the research questions or the interview guide; see [category-development.md](category-development.md) for inductive and combined routes.
3. **Code the data with main categories.** First coding cycle, applied to the complete material.
4. **Form subcategories inductively.** Compile all passages coded to each main category, derive subcategories from that compilation, then finalize the category system and coding guide.
5. **Code the data with subcategories.** Second coding cycle: recode the complete material with the differentiated system.
6. **Simple and complex analyses.** Write thematic summaries per case and category, build a cases-by-categories matrix, then analyze within categories, across categories, across cases, and by attributes.
7. **Write up results and document procedures.**

## Evaluative QCA: Seven Phases

1. **Initial work with the text.** Read, write memos, and write case summaries. Where a structuring QCA has already run, shorten this phase by re-reading its results for categories and passages suited to evaluation rather than repeating it.
2. **Define an evaluative category.** Justify why this category is assessed rather than merely described, and tie it to the research question. Evaluative coding is expensive, so select few categories, and confirm the data can support an assessment for nearly all cases.
3. **Identify and code relevant text passages.** Process the entire dataset and mark every passage carrying information on the category. Do not skip to developing levels: the levels must be grounded in the passages actually present.
4. **Develop levels.** Define the value set — ordinal, such as strong / little / none, or dichotomous. Write a decision rule and an anchor example for each level. Pilot, discuss ambiguous cases, and revise.
5. **Evaluate and code all cases.** Assign one value per case per evaluative category.
6. **Simple and complex analyses.** Build case profiles, compare evaluations against thematic categories and attributes, use quote matrices and descriptive cross-tabs, then interpret why cases receive different evaluations and examine boundary cases.
7. **Write up results and document the process.** State the evaluation standard openly; it is the researcher's, not the data's.

## Type-Building QCA: Nine Phases

1. **Determine purpose, goal, and focus.** Decide how complex the typology should be and which attributes are primary. Exclude from the attribute space whatever the typology is meant to explain, or the analysis becomes tautological — a typology of environmental awareness should not be built from behavioural attributes if the aim is to examine its effect on behaviour.
2. **Define relevant dimensions and determine the attribute space.** Select attributes from the theoretical framework and research question. Limit them to attributes documented for enough cases; an attribute present in 2 of 40 respondents cannot differentiate. Check whether the existing thematic or evaluative coding already supplies the information, or whether new coding is needed.
3. **Code the selected data.** Build on existing thematic or evaluative coding where it exists; otherwise code the material to the selected attributes and characteristics first.
4. **Determine the type-building method and construct the typology.** Choose deliberately:

   | Method | When it fits | Description burden |
   |---|---|---|
   | Monothetic homogeneous attribute types | Two or three attributes with few characteristics | Largely self-explanatory |
   | Type building by reduction | More features and characteristics; the flexible middle option | List the attribute combinations that were merged |
   | Polythetic type building | Numerous characteristics and a genuinely multidimensional attribute space | Requires describing each type's position in the attribute space |

   Set the number of types from natural groupings in the field, the number of cases, practical relevance, and whether the intended audience can hold the distinctions. Do not fix the number in advance; construct two or three alternative groupings and compare them.
5. **Assign all cases to types.** Assignment is exclusive — a case belongs to one type, not two.
6. **Describe the typology and the individual types.** Name and define each type, select prototypes or illustrative cases, and locate each type in the attribute space where the method requires it. Retain atypical and mixed cases where they are analytically meaningful.
7. **Analyse relationships between types and secondary information.** Examine how types relate to sociodemographic and other case-level information that was deliberately kept out of the attribute space.
8. **Analyse relationships between types and other categories.** Disaggregate the coded material by type and explore how type membership relates to the study's other topics.
9. **Write up results and document the process.** State the conditions, consequences, limits, and transferability of the typology.
