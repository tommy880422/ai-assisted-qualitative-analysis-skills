# Three QCA Workflows

Each workflow below follows the phase structure and numbering of the source method. Keeping the numbering in the method section lets a reader match the reported procedure to the published one (this is this skill's advice, not a requirement of the book).

## Structuring QCA: Seven Phases

1. **Initial work with the text.** Read, write memos, mark notable passages, and produce brief case summaries.
2. **Develop main categories.** Usually derived deductively from the research questions or the interview guide; see [category-development.md](category-development.md) for inductive and combined routes.
3. **Code the data with main categories.** First coding cycle, applied to the complete material.
4. **Form subcategories inductively.** Do this at least for the categories central to the study; most projects do not differentiate every main category (pp. 106, 111). For the chosen main category, compile all passages coded to it (text retrieval), derive subcategories from that compilation, order them, and write definitions with prototypical quotes (pp. 106–107). Use enough material: merging subcategories later is easy, adding new ones later means coding the data again (p. 110).
5. **Code the data with subcategories.** Second coding cycle: go through the data again and assign the passages already coded under each main category to its new subcategories (p. 110). Phases 4 and 5 run in cycles — develop the subcategories for one main category, apply them to all cases, then move to the next main category (p. 111).
6. **Simple and complex analyses.** As an optional intermediate step after the second cycle, write thematic summaries per case and category from the cases-by-categories matrix (pp. 111–114). Then choose among the analysis options in Figure 5.6 (p. 115): category-based analysis of the main categories (the usual starting point), relationships between subcategories within a main category, pairwise relationships between categories, multidimensional configurations, case- and group-based comparisons, tabular case overviews, in-depth interpretation of selected cases, and visualizations. These are options; no project has to use all of them.
7. **Write up results and document procedures.**

## Evaluative QCA: Seven Phases

1. **Initial work with the text.** Read, write memos, and write case summaries. Where a structuring QCA has already run, shorten this phase by re-reading its results for categories and passages suited to evaluation rather than repeating it.
2. **Define an evaluative category.** Justify why this category is assessed rather than merely described, and tie it to the research question. Evaluative coding is expensive, so select few categories, and confirm the data can support an assessment for nearly all cases.
3. **Identify and code relevant text passages.** Process the entire dataset and mark every passage carrying information on the category. If the category has already been coded thematically, build on that coding and skip this phase (p. 127). Either way, levels are developed from the compiled passages, not before them.
4. **Develop levels.** Compile the coded passages case by case and decide how finely to differentiate. As a rule distinguish at least three characteristics: high, low, and “unable to classify” — the last is almost always needed because the data rarely cover every case (p. 127). Write a definition, coder notes, and a prototypical example for each level. Test on part of the data (10–25% of cases, drawn from every group) and revise; phases 4 and 5 may cycle (pp. 127–128).
5. **Evaluate and code all cases.** Two strategies: assess all relevant passages of a case together and code one value per case, or code each passage separately so that ambivalence within a case stays visible (p. 131). Note in a memo why an uncertain case was classified one way and not another.
6. **Simple and complex analyses.** Build case profiles, compare evaluations against thematic categories and attributes, use quote matrices and descriptive cross-tabs, and analyse selected cases in depth (Figure 6.2, p. 132).
7. **Write up results and document the process.** Describe each evaluative category and its levels, the criteria for assigning them, how many and which cases received which value, and how ambiguous assignments were handled (p. 137). The standard is the researchers' own evaluation standard (p. 36); state it openly.

## Type-Building QCA: Nine Phases

1. **Determine purpose, goal, and focus.** Decide how complex the typology should be and which attributes are primary. Exclude from the attribute space whatever the typology is meant to explain, or the analysis becomes tautological — a typology of environmental awareness should not be built from behavioural attributes if the aim is to examine its effect on behaviour.
2. **Define relevant dimensions and determine the attribute space.** Select attributes from the theoretical framework and research question. Limit them to attributes documented for enough cases; an attribute present in 2 of 40 respondents cannot differentiate. Check whether the existing thematic or evaluative coding already supplies the information, or whether new coding is needed.
3. **Code the selected data.** Build on existing thematic or evaluative coding where it exists; otherwise code the material to the selected attributes and characteristics first.
4. **Determine the type-building method and construct the typology.** Choose deliberately:

   | Method | When it fits | Description burden |
   |---|---|---|
   | Monothetic homogeneous attribute types | Two or three attributes with few characteristics | Largely self-explanatory |
   | Type building by reduction | More features and characteristics; the flexible middle option | List the attribute combinations that were merged |
   | Polythetic type building | Numerous characteristics and a genuinely multidimensional attribute space | Requires describing each type's position in the attribute space |

   Set the number of types from natural groupings in the field, the number of cases, practical relevance, and whether the intended audience can hold the distinctions. Do not fix the number in advance; construct two or three alternative groupings and compare them.
5. **Assign all cases to types.** Assignment is exclusive — a case belongs to one type, not two.
6. **Describe the typology and the individual types.** Name and define each type, select prototypes or illustrative cases, and locate each type in the attribute space where the method requires it. (This skill adds: keep atypical and mixed cases in view where they are analytically meaningful; the book's phase 6 does not discuss them.)
7. **Analyse relationships between types and secondary information.** Examine how types relate to sociodemographic and other case-level information that was deliberately kept out of the attribute space.
8. **Analyse relationships between types and other categories.** Disaggregate the coded material by type and explore how type membership relates to the study's other topics.
9. **Write up results and document the process.** Report the objective of type building, the attribute space and underlying data, the construction process, a detailed description of the typology and the individual types, the number of cases per type, the results of the relationship analyses, and considerations on generalizing the results (p. 156).
