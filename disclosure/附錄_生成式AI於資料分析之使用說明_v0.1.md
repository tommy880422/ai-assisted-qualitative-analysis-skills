## 二、固定指示（每次分析都適用的規範）

生成式工具的輸出取決於指示，本研究把指示分成三層，前兩層是固定的。

1. **方法指示（技能說明檔）。** 研究者事先把方法學工具書整理成說明檔，Claude 在進行分析前先讀取，內容是分析步驟、必要的產出與禁止事項。本研究實際使用的有四份，對應的工具書見第六節。
   - `do-qualitative-content-analysis`：Kuckartz 與 Rädiker 的質性內容分析（類別的演繹與歸納發展、編碼指引、個案與類別並重、品質檢核）。
   - `apply-jobs-to-be-done-theory`：用途理論的構念界定與分析（以 Christensen 等人的版本為主，與其他版本區分）。
   - `analyze-focus-group-data`：焦點團體資料的分析（保留團體互動、共識與分歧、沉默與缺席）。
   - `use-nvivo-for-qualitative-analysis`：把已定的分析設計落實到 NVivo。
   這些說明檔都要求方法與詮釋上的決定由研究者做，例如 NVivo 的說明檔明訂，詞頻、自動編碼、情感分析或 AI 產生的主題，未經研究者回到脈絡分析，不得當作研究發現。
2. **編碼手冊。** 類別定義、何時編與不編、判斷規則 1–40、邊界案例決定。手冊自 v0.1（2026-10-09）修訂至 v0.6.6（2026-11-10 定稿），每一版的修改內容、依據與「誰草擬、誰決定」都記在手冊的版本紀錄。Claude、Codex、Gemini 都依同一份手冊工作。
3. **各階段的指令。** 見第三節。

另有兩項固定的工作規則：(1) 外部工具（Codex、Gemini）的產出一律先由 Claude 對照手冊與原文核對，再交研究者；(2) 文獻的檢索與引用不交給外部工具，引用須對得到 DOI 或 PMID。

## 三、各階段的分工與指令

每一階段列出人工智慧工具做了什麼、研究者做了什麼，以及該階段使用的指令。指令可直接複製，【 】內換成自己的研究內容。每一則都把工具該做與不該做的事、以及由研究者決定的事寫進指令。

### 階段 0　錄音轉錄與逐字稿整理（各場訪談後至 2026-10-30）

- **工具的工作：**
  - jt-live-whisper 在研究者的電腦上把錄音轉成附時間標記的逐字稿（第一個來源）。
  - NotebookLM 由錄音產生另一份逐字稿（第二個來源）。
  - Claude 逐段比對兩個來源，整合成一份逐字稿，並標出兩者不一致、需要聽錄音才能確定的地方；之後把六場逐字稿整理成同一格式（標準版，加行號），並轉出代號化版本。
- **研究者的工作：** 對照錄音逐句校對整合後的逐字稿，決定不一致之處以何者為準，確認每段的說話者；校對完成的版本才進入分析。
- **指令：**

  整合兩個來源的逐字稿

  ```text
  附件是同一場訪談的兩份逐字稿，分別由【轉錄工具甲】和【轉錄工具乙】產生。
  請逐段比對，整合成一份逐字稿：
  1. 兩份一致的地方直接採用。
  2. 兩份不一致的地方，不要自行決定，把兩種寫法並列，標上【待確認】與時間點，我會回去聽錄音。
  3. 說話者無法確定時標【說話者待確認】，不要猜。
  4. 保留語氣詞、重複與停頓，不要潤飾，不要補上錄音裡沒有的字。
  最後列出所有待確認之處的清單。
  ```

  統一逐字稿格式

  ```text
  這是【N】場訪談的逐字稿，格式不一致。請先告訴我哪一份最適合當標準格式與理由。
  我同意後，把其中一份改成標準版給我看（另存新檔，原檔不動，每段加行號），我確認模板後再處理其他場。
  只改格式，不改任何一個字的內容。
  ```

### 階段 1　理論架構與初步分析（2026-10-06 至 10-10）

- **工具的工作：** Claude 依用途理論對前四場做初步分析；整理 Christensen 等人的文獻，提出分析架構的兩種做法供研究者選擇。
- **研究者的工作：** 決定以 Christensen 等人（2016）的版本為主軸、不採用任務地圖；決定分析以四個組別為單位。
- **指令：**

  依理論做初步分析、選擇分析架構

  ```text
  附件是【N】場訪談的逐字稿，各場受訪者的特徵是【分組方式】。
  請以【理論名稱與主要文獻】為視角做初步分析，說明各組資料中與理論各構念有關的內容，每一點附原句與行號。
  這個理論有不同的版本或做法時，請並列各自的適用條件與對我的研究設計的影響，由我選擇，不要替我決定。
  只根據逐字稿，不要加入資料裡沒有的推論。
  ```

### 階段 2　建立與修訂編碼手冊（2026-10-09 至 11-10）

- **工具的工作：** Claude 依理論架構草擬演繹類別（K、B 等），由第一場逐字稿歸納實質代碼（D），之後每編一場就提出新增的代碼；把規則不清、可以有兩種判法的地方整理成「待決事項」，附原文與選項。Codex 審閱手冊三輪（v0.6 至 v0.6.3）。
- **研究者的工作：** 逐項裁決待決事項；決定類別定義的寬嚴；手冊每一版經研究者審閱。
- **指令：**

  由理論建立演繹類別、由資料歸納實質代碼

  ```text
  我的研究以【理論名稱與主要文獻】為分析視角，分析方法是【例如 Kuckartz 與 Rädiker 的結構式質性內容分析】。
  請依附件的理論文獻草擬演繹類別，每個類別寫出：定義、何時編、何時不編、與相近類別的區辨、一個例句。
  再讀【第一場】逐字稿，歸納理論類別以外的實質代碼，每個代碼附原句與行號。
  定義不清或可以有兩種判法的地方，不要自己決定，列成待決事項，附原文與選項，由我決定。
  ```

  先試編再全面編碼

  ```text
  請從各場挑【40】個片段試編，先給我抽樣清單和挑選理由，我確認後再編。
  試編後，把規則不夠清楚、你沒有把握的地方列成問題，附前後文，一題一題問我。
  ```

### 階段 3　六場的編碼（2026-10-10 至 10-17；會後回覆至 11-10）

- **工具的工作：** Claude 依手冊對每個片段提出編碼（實質代碼、用途構念、面向與各描述標記），每筆附依據原句與行號；手冊改版後依新版重判。各場編碼表的「初步編碼者」欄因此都記為 Claude。
- **研究者的工作：** 逐場審閱，對有疑問的列回到前後文判斷並指示修改；確認後才進行下一場。受訪者會後的書面回覆與補訪由研究者蒐集、貼入，再比照團體資料編碼。
- **指令：**

  依手冊逐場編碼

  ```text
  請依編碼手冊【版本】編碼【第 N 場】。每筆編碼要有：片段行號、依據原句（必須是片段內的原文）、各類代碼、判斷理由。
  手冊沒有涵蓋的情形不要硬編，標為待決並說明。
  編完一場先給我看，我確認後才編下一場。
  ```

### 階段 4　人工智慧輔助檢視與編碼審視（2026-10-15 至 10-19；11-10；11-23）

- **工具的工作：**
  - 2026-10-18，Codex 與 Gemini 各自依手冊 v0.6.6 檢視當時的全部 861 筆編碼。面向（B）與經驗依據（I）採盲判，兩個工具看不到實質代碼與 Claude 的編碼；用途構念（K）則提供實質代碼但不提供 Claude 的 K。給兩個工具的指引開頭寫明「你在做 AI 輔助檢視。你看不到實質代碼 D，也看不到第一編碼者的代碼。」
  - 兩個工具答案相同、但與原編碼不同的 294 列，Claude 逐列對照手冊與原文複核，修改或維持並寫下理由；依手冊無法判定的列交研究者。這次檢視找出原編碼三類系統性的錯誤（例如把身體不適誤編為功能面向），已全部更正。
  - 2026-11-10，Claude 以規則檢查全部編碼並列出需要研究者判斷的列。2026-11-23，Codex 兩度驗收交給指導教授的編碼資料（規格、內部一致性、逐字稿與編碼的對應）。
- **研究者的工作：** 決定檢視的做法與順序；裁決交回的列（2026-10-19）；2026-11-10 以對話方式逐項評定審視清單；2026-11-23 逐項決定驗收發現的問題如何處理；對收音不清的片段重聽錄音。
- **指令：**

  以第二個人工智慧工具檢視編碼（盲判）

  ```text
  你在做 AI 輔助檢視。下面是編碼手冊中【類別】的定義與規則，以及訪談片段（已代號化）。
  你看不到原編碼者的代碼。請依手冊獨立判斷每個片段的【類別】，並寫出依據的原句與理由。
  只依手冊判斷，不要加入手冊沒有的類別。
  ```

  複核不一致之處

  ```text
  請比對原編碼與檢視結果。不一致的列逐筆回到手冊與原文複核：
  能依手冊判定的，修改或維持，並寫下理由；依手冊無法判定的，不要決定，列出來附原文與兩種判法，由我裁決。
  每筆修改都要留下原值、新值、理由與日期。
  ```

- **檢視前的相同比例（僅供了解檢視的範圍，不是編碼者間一致性）：** 面向 77%、經驗依據 84%、用途構念 54–55%（Claude 對 Codex、對 Gemini）。用途構念的規則最多、邊界最細，差異也最多，後續的修訂集中在這一類。

### 階段 5　飽和評估與用途的歸納（2026-10-17；11-08 至 11-23）

- **工具的工作：** Claude 計算各場新增的實質代碼並彙整成飽和評估；把編了「想要的進展」的列彙整成用途歸類表。Codex 在看不到 Claude 結果的條件下獨立提出用途的分類（2026-11-08），並就六種用途能否成立提出意見（2026-11-11）。
- **研究者的工作：** 比較兩份分類後定案；決定用途為六種、主要用途的門檻（同組兩位以上、至少一位來自團體討論）、一般看法須連回本人處境才計入；決定各用途的名稱。
- **指令：**

  飽和評估

  ```text
  請計算各場新出現的【實質代碼】數目，依場次列表，並指出後面幾場新增的代碼各是什麼、屬於新的概念還是既有概念的變化。
  資料是否飽和由我判斷，請只提供數字與依據。
  ```

  歸納與檢驗研究結果的類別

  ```text
  請把編了【核心類別】的列依【分析單位，例如組別】彙整，提出歸納的方案，每一類附全部支持的編碼 ID。
  另請說明每一類的反例，以及哪些列放不進任何一類。分類由我比較後定案。
  ```

### 階段 6　研究結果的撰寫（2026-11-10 至 11-25）

- **工具的工作：** Claude 依用途歸類表與編碼草擬第四章的段落與表格、挑選候選引文並附編碼 ID；逐筆核對正文的數字與引文是否對得到編碼與逐字稿。
- **研究者的工作：** 決定章節架構與呈現方式、逐段修改文字、選定引文、自行把定稿貼入論文檔。詮釋與結論由研究者負責。
- **指令：**

  草擬研究結果

  ```text
  請依【歸類表】與編碼草擬【章節】的段落。每個論點要對得到編碼 ID，候選引文附行號並逐字照錄。
  只寫資料支持的內容；詮釋的部分標明是你的建議，由我決定是否採用與如何修改。
  ```

  核對研究結果與資料

  ```text
  請逐筆核對這一章的每個數字與每段引文：數字要對得到編碼表，引文要與逐字稿原文逐字相符並註明行號。
  對不上的列出來，不要自行修改正文。
  ```

## 四、研究者保留的決定

下列事項都由研究者決定，工具只提供選項、依據與草稿。

1. 理論版本與分析方法的選擇。
2. 類別的定義、判斷規則與每一版手冊的採用。
3. 邊界案例與待決事項的裁決（記於手冊「邊界案例決定」與各筆的分析備忘）。
4. 人工智慧輔助檢視交回的列，以及驗收發現的問題如何處理。
5. 用途的數目、名稱、定義與主要用途的門檻。
6. 引文的選擇與研究結果的詮釋。

每一筆編碼的修改都在分析備忘留下原因與日期；手冊的版本紀錄註明每次修改是「研究者決定」「Claude 草擬」或「Codex 第二意見、Claude 驗收」。這些紀錄構成本研究的稽核軌跡。

## 五、資料保護

- 交給 Codex 與 Gemini 的資料都是代號化版本，受訪者、主持人與機構名稱以代號取代，送出前以代號對照表與各場說話者名單掃描，確認沒有真實姓名。
- Claude 讀取的是逐字稿的標準版（研究者 2026-11-26 確認）。標準版統一了格式並加上行號，說話者仍以受訪者在團體中使用的稱呼（暱稱或姓名）標示，不是代號化版本。Claude 在研究者的電腦上讀取檔案，內容會傳送到服務商的伺服器運算。代號化版本是由標準版轉出，供 Codex、Gemini 與對外呈現使用。【待確認 1】這項做法是否在 IRB 核准的資料處理方式與受訪者同意書的範圍內，請研究者對照核准文件，並與指導教授確認論文的寫法。
- 代號與化名的對照表只存放在研究者的電腦，不放入論文。
- 錄音檔只用於轉錄：jt-live-whisper 在本機處理，錄音不離開研究者的電腦；NotebookLM 是雲端服務，使用時錄音上傳至 Google。【待確認 6】第三章第四節與第七節現在寫「錄音不上傳至網路服務」，與使用 NotebookLM 的做法不一致，須改寫；上傳錄音是否在 IRB 核准與同意書的範圍內，請一併對照核准文件。

## 七、限制

1. 生成式工具會誤讀語意，也會前後不一致。本研究的輔助檢視就找出原編碼三類系統性的錯誤。研究者的審閱與裁決是必要的把關，但無法保證沒有殘留的錯誤。
2. 人工智慧輔助檢視不是獨立的人類第二編碼者。三個工具可能有相近的偏誤，彼此相同不代表正確，本研究因此不報告編碼者間一致性。
3. 同一指令在不同時間、不同模型版本下的輸出不會完全相同。本研究以手冊、依據原句與修改紀錄保留可查核性，而不是以重複執行來保證再現。
4. 初步編碼由工具提出，研究者的判斷可能受到既有建議的影響（定錨）。待決事項要求工具並列選項與原文，是為了降低這項影響。
